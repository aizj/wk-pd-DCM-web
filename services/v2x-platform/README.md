# 数据上车服务平台 · P0-S4 参考实现

对应《数据上车服务平台 · 订阅与配置规划设计》附录 G 的任务包切片：
T-03 主数据、T-04 授权与白名单、T-05 对外提供门禁、T-09 规则引擎（部分）、
T-10 订阅主流程（骨架）、T-22 审计。

**按默认分支（附录 F 六问未获答复 → 附录 E 的 S4）实现**：门禁默认 `UNCONFIRMED`，
车企订阅可进沙箱、进不了生产；示范车队按测试数据使用协议可进预生产。

## 运行

```bash
python3 main.py demo          # 建库、造数、跑一遍默认分支
python3 main.py serve 8787    # 启动 API 与控制台
python3 -m unittest discover -s tests -v
```

浏览器打开 http://127.0.0.1:8787

## 已实现的规则

| 规则 | 含义 | 实现位置 |
|---|---|---|
| R-00 | 对外提供门禁：授权路径未确认时不得向车企、图商提供 | `rules.check_r00` |
| R-01 | 订阅范围 ⊆ 授权白名单 | `rules.check_r01` |
| R-03 | 订阅有效期 ≤ 授权有效期 | `rules.check_r03` |
| R-21 | 范围 ⊆ 已发布路口 | `rules.check_r21` |

规则在**提交、审批、生效前**三处调用同一套实现（当前切片在状态迁移处终检）。

## 设计要点

- **审计哈希链**：每条审计记录链接上一条的哈希，篡改任意一条 `audit_verify()` 即失败。
- **白名单只增版本**：`grant_scope` 按 `(grant_id, version)` 存，历史可回溯，收缩前可做影响分析。
- **门禁双人复核**：`set_gate` 强制录入人与复核人不同。
- **拦截也要留痕**：被规则挡下的迁移写 `SUB_TRANSITION_DENIED` 审计。

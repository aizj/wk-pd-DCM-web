# 济南车路云数据上车服务运营平台

平台端新工程基线。项目与既有 `platform/` 演示工程、`移动端/`、车端和 OEM 系统隔离。本阶段先建立公共壳层、模块路由、权限骨架、状态字典和可替换的数据网关，不实现生产业务裁决。

## 当前范围

- React 19＋TypeScript＋Vite 的企业级 SPA 基线；
- FR-1～FR-6 模块边界和导航注册；未建设的功能在导航中标为“建设中”且不可点击，已交付的只读切片可直接进入；
- FR-2 P01～P15 页面交付单元路由；
- P01申请管理和P15运营工作台；P02支持从服务目录/企业权益上下文创建演示环境申请草稿，草稿仅保存在浏览器会话；固定示例仍可只读查看；
- P03提交确认、P04五层准入检查、P05检查项详情、P06补正任务、P07单条审批处理和P08分支化审批意见；P06支持提交材料引用和申请重新检查意图，均保留独立复核边界；
- P07审批队列只读切片：按处理人、状态、风险和环境筛选审批事项，再进入单条审批处理；不改变审批结果；
- P09订阅实例列表和P10订阅详情的只读骨架；按原子实例分别展示生命周期、控制、开通条件及未接入的外部事实；
- P14运行诊断只读切片：按实例串联配置、联合测试、发布、交付证据和事件，给出事实驱动的下一步建议；不生成新的运行状态；
- P11版本比较只读切片：按订阅选择基准/目标版本，查看字段级变化、影响程度和重新测试要求；不执行版本切换；
- P12变更与续期：选择续期、范围收窄或服务参数调整，完成基线/权益影响评估；满足门禁时可提交带幂等键的待审批变更申请并查看回执，不直接生成新Revision；
- P13控制与退出：选择暂停、恢复或终止意图，核对控制门禁、职责分离和退出清单；满足对象状态和说明要求时可提交带幂等键的待核验控制计划，不直接切换订阅或实例状态；
- FR-3配置管理切片：配置版本列表、环境/状态筛选、参数分组、必填项状态和配置校验门禁；支持提交配置变更/回退申请并查看本会话待审批回执，不直接保存或发布真实参数；
- FR-4联合测试切片：测试任务列表、Profile/输入门禁、测试项结果、证据等级和阻断原因；测试负责人可提交启动测试意图并查看排队回执，不直接回写测试结果；
- FR-4服务发布切片：发布计划、版本与门禁、灰度/全量策略、节点回执、回退边界和异常状态详情；具备发布权限的账号可提交启动发布意图并查看排队回执，不直接回写节点结果；
- FR-1服务目录与权益切片：服务能力、场景、接入Profile、企业授权范围和有效期边界；目录详情匹配当前租户有效权益，带服务/权益上下文进入申请向导，不修改授权事实；
- FR-5运行与交付证据只读切片：按投递、接收、展示、交互分层查看证据等级、事件明细、关联号和链路状态；不由订阅或发布状态推断车辆事实；
- FR-5事件与工单切片：异常类别、严重度、处理状态、根因、影响范围、处置时间线和恢复证据；具备确认、转派、恢复确认三类处置意图和幂等回执，但不直接改写事件事实；
- 安全与审计访问控制切片：访问控制总览、角色管理、角色权限配置、主体授权、访问复核、权限目录和审计查询分别使用独立路由；具备配置权限的账号可按模块/风险/关键字筛选权限矩阵并批量编辑草稿，按主体/角色/环境/状态筛选授权实例，查看角色继承与显式授权来源、有效授权和策略模拟；访问复核支持按主体、租户、角色、环境和状态形成保留/收窄/撤销待审批结论；角色模板配置、授权申请和复核申请均不绕过审批修改真实授权；授权申请历史和动态草稿在网关层按目标租户与当前环境隔离；
- FR-6租户与接入切片：独立的合作方/租户、ApplicationClient、环境、端点引用、凭证引用和配额工作台；`/fr1/partners` 负责准入对象，`/fr1/endpoints` 负责逐环境端点、网络区、认证方式、凭证生命周期和接入网关六项核验记录；端点级连接测试、凭证轮换/吊销请求必须绑定端点与环境，并保留逐项回执。支持按主体类型、状态、环境查询，查看准入详情，提交带幂等键的待审核接入申请，以及冻结、恢复、退出等受权限控制的操作意图。页面不替代“主体授权”，不展示私钥，也不直接开通生产身份；查询和操作均在网关层执行租户/环境范围复核。
- 安全与审计审计查询与对接状态只读切片：查看关键操作留痕和各业务系统数据域接入情况；不修改审计事实或连接配置；路由和页面统一复用 `AuthProvider` 注入的身份上下文。
- RBAC/ABAC/对象状态守卫与职责分离的统一策略层；
- 17 类 FR-2 状态对象/维度的共享字典；
- TanStack Query 业务网关与 Mock 实现、提交/决定幂等语义、全局错误边界和六态组件；
- Vitest 基础单元测试与跨目录边界检查。

## 启动

```bash
npm install
npm run dev
```

默认地址：`http://127.0.0.1:5173`。

## 验证

```bash
npm run check
```

## 开发边界

1. 当前 Mock 只验证页面、路由、守卫与契约语义，不代表真实接口或业务成功；所有结果均显式标注“未ACTIVE、未发布、未上车”。
2. 状态变更、审批、激活、暂停、恢复、终止和发布不得在前端自行推断。
3. 真实接口接入前必须冻结 OpenAPI/AsyncAPI、ReasonCode、ETag、幂等键和权限映射。
4. 移动端、车端、OEM 系统和既有演示项目均不在本工程修改范围。
5. 未建设模块保留路由，在导航中显示为“建设中”且禁用；直接访问路由仅显示不可办理说明，不宣称已交付。
6. 当前可进入已交付的工作台、服务目录、租户与接入、端点与凭证、申请、订阅运营、配置、测试发布、运行监控和安全审计切片；检查项、补正、审批处理和订阅详情由业务对象进入。
7. 演示提交与审批回执仅保存在浏览器会话中；更换浏览器或清理会话数据后会重置。

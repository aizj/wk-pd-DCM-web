# 平台端界面与业务流程修正记录

## 修正目标

本轮针对“文案像研发规格、页面层级和办理顺序不符合平台软件习惯”的反馈，按运营人员的任务而非内部对象模型组织界面。页面首先回答“这是什么申请、当前能做什么、为什么不能做、下一步去哪”，对象编号和校验码作为可追溯信息保留，但不再占据主视觉。

## 已修正

| 问题 | 本轮处理 |
|---|---|
| `CURRENT`、`PASS_WITH_CONDITIONS`、`SoD` 等机器状态直接暴露 | 统一翻译为“当前有效”“有条件通过”“职责冲突检查”等业务语言；原始编码保留在模型中 |
| 页面编号、FR 编号和 Mock 边界文案充斥页头 | 页头改为业务名称；演示边界集中说明，技术信息折叠展示 |
| 详情页、补正页、审批决定页位于一级导航 | 技术详情页继续隐藏在一级导航；一级导航只展示业务域入口，详情由申请、检查项、审批单或订阅实例进入 |
| 首页展示研发开工门禁和与列表不一致的指标 | 改为与两条示例申请一致的运营指标和待办入口 |
| 同一申请既“审批中”又允许重新提交 | 分离“待提交草稿”与“审批中申请”；提交后生成对应的新审批单 |
| 附条件、退回、拒绝共用同一份不完整表单 | 按审批结论切换专属必填字段，原因选项随结论变化；未处理硬性条件时禁用无条件批准 |
| 退回后跳转到另一份示例草稿 | 退回入口保留原申请只读说明；申请人需依据退回要求重新创建草稿，不伪造后继版本 |
| 同一检查项被两个检查批次复用 | 每个检查批次使用独立的检查项编号；详情返回原检查批次 |
| 深层页面只显示当前页，用户难以判断所在业务域 | 顶栏面包屑统一补充业务域层级，详情页按“业务域 > 入口页 > 当前详情”表达 |
| 权限标签把“拥有权限”和“已经提交/生效”混在一起 | 统一改为“权限 · 已授权”；申请、排队、审批和实际生效仍由页面状态单独表达 |
| 跨模块详情链接带查询条件但目标列表不接收 | 配置管理、联合测试列表读取 `configurationId` / `qualificationId`，进入后保留来源对象筛选上下文 |
| 新建草稿和既有草稿共用固定示例上下文 | 草稿按服务、权益和申请编号生成独立幂等键；既有会话草稿按申请编号回载，找不到时明确提示，不再回退为示例数据 |
| 部分状态筛选显示原始英文状态码 | 补齐“已撤回”“已放弃”“申请已过期”等业务文案，并统一状态标签颜色语义 |
| 准入检查和检查项详情使用固定版本、固定返回批次 | 徽标从实际检查结果读取版本/状态；检查项保留来源批次参数，支持动态检查批次返回 |

## 当前仍是演示切片

- P02支持从有效服务权益上下文创建演示环境草稿，并继续进入P03；固定示例仍保持只读，草稿不写入生产系统。
- P07已提供“我的待办 / 全部事项”筛选和单条审批处理；“已办 / 委托 / 超时”仍待真实审批中心接口接入。
- 补正材料真实上传、独立复核、重新检查和真实服务开通仍未接入接口；当前仅支持引用已登记材料并提交处理意图回执。
- 浏览器会话内的 Mock 回执用于交互验收，不具备生产审计或持久化效力。

下一开发阶段应先补真实接口契约及服务端门禁，再逐步扩大可办理操作；未实现页面继续保持只读、禁用或明确的不可办理状态。

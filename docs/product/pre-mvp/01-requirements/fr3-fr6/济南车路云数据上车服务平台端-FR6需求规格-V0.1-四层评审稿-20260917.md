## 0. 结论、范围与责任边界

FR-6 解决的是“平台能否在同一套有权规则、可信身份、受控契约和可审计运营基础上工作”。它不新增一级导航，而是把既有 PG02、PG07、PG16、PG23、PG01 的基础治理子流程下沉为可评审需求。FR-6 只拥有平台基础对象，不得修改 FR-1～FR-5 的业务结论。

| 对象/事实 | 唯一 Owner | FR-6 权限与边界 |
|---|---|---|
| `ProjectProfileVersion` / `StandardAdoptionDecision` | 项目 Profile Owner | 记录已签认采用规则、扩展和有效期；不自行解释法律效力 |
| `PartnerProfile` / `ApplicationClient` / `EnvironmentBinding` | 合作方接入 Owner | 管理主体、应用和环境准入；不代替 FR-1 的车型能力/服务权益 |
| `EndpointRegistration` / `CredentialReference` / `TrustDecision` | 接入安全 Owner | 管理引用、状态和轮换流程；不保存私钥正文、不代替外部 CA/KMS |
| `IdentityPrincipal` / `RoleAssignment` / `AccessReview` / `SoDException` | 安全管理员 | 管理平台访问；前端可见性不替代服务端授权 |
| `RetentionPolicyVersion` / `LegalHold` / `DeletionJob` / `EvidenceExport` | 数据治理 Owner | 管理平台内数据生命周期和导出决定；不得删除仍受 Hold/法定保留约束的数据 |
| `ContractArtifactVersion` / `SandboxWorkspace` / `ConformanceRun` | 集成与测试 Owner | 管理契约、样例、Mock 和一致性结果；不把沙箱通过等同生产准出 |
| `DictionaryVersion` / `PlatformSettingVersion` | 字典/平台 Owner | 管理跨页面枚举、原因码和平台开关；不覆盖领域状态机 |
| `NotificationPolicyVersion` / `DutyRosterVersion` / `EscalationCase` | 运营保障 Owner | 管理通知和升级；通知送达不等于事件解决 |

## 1. 用户故事

### US-FR6-01 让项目规则成为一致依据

作为项目规则负责人，  
在标准、政策、合同和项目决定共同约束数据上车服务时，  
我希望形成一份可追溯、可版本化且由有权角色确认的项目规则基线，  
以便产品、研发、测试、OEM 和运营使用同一套有效规则判断业务。

- AC1：在采用依据和责任人明确时，当我组织规则确认，用户应能够获得完整且无冲突的项目基线，并且每项决定可追溯到依据与签认人。
- AC2：在条款冲突、依据失效或解释未决时，当我继续推进，用户应能够识别未决范围和责任人，并且未确认内容不会被当作生产规则。
- AC3：当规则基线生效或被替代后，用户应能够判断哪些服务、契约和测试受到影响，并且历史版本仍可复核。

### US-FR6-02 可信地接入合作方和应用

作为合作方接入负责人，  
在 OEM/TSP 准备接入开发、测试、预生产或生产环境时，  
我希望确认主体、协议、应用、端点、凭证和责任联系链均满足目标环境要求，  
以便只让有权且可协同的接入对象进入后续服务申请和联调。

- AC1：在材料和责任链完整时，当我办理接入，用户应能够获得范围明确的合作方、应用和环境身份，并且不同环境不会混用凭证或数据。
- AC2：在协议临期、端点异常、凭证失效或主体不明时，当我继续办理，用户应能够获得明确修正路径，并且生产访问不会被默认放行。
- AC3：当接入关系建立、冻结或退出后，用户应能够理解对服务、订阅和联调的影响，并且相应责任方可继续处理。

### US-FR6-03 让平台访问始终最小且可复核

作为安全与合规负责人，  
在人员、服务账号和跨组织成员需要查看或操作不同环境与数据时，  
我希望按职责、范围、期限和风险授予并周期复核访问，  
以便降低越权、职责冲突和长期遗留权限风险。

- AC1：在岗位和任务已确认时，当我批准访问，用户应能够获得完成工作所需的最小范围，并且高风险职责保持分离。
- AC2：在权限冲突、身份失效或授权到期时，当用户继续工作，用户应能够获知限制与修正路径，并且无权操作不会产生业务结果。
- AC3：当访问被复核、收窄或撤销后，用户应能够追溯决定与影响，并且服务账号和自然人账号分别治理。

### US-FR6-04 可控地管理数据和证据生命周期

作为数据治理与审计负责人，  
在授权材料、测试数据、事件明细、车端反馈和审计证据持续产生时，  
我希望按用途、分类、保留依据和争议状态管理访问、保留、冻结、导出与删除，  
以便既满足取证和审计，又避免超期持有或不当传播。

- AC1：在策略有效且无保留阻断时，当我执行生命周期任务，用户应能够获得范围清楚的处理结果和证明，并且必要证据仍可追溯。
- AC2：在 Legal Hold、引用依赖、权限不足或删除失败时，当我继续处理，用户应能够看到阻断、影响和下一责任人，并且数据不会被静默删除。
- AC3：当导出或删除完成后，用户应能够向审计方说明用途、范围、审批和结果，并且敏感正文不出现在普通日志中。

### US-FR6-05 以一致契约完成接入和验证

作为 OEM 接入工程师和联合测试人员，  
在准备对接服务目录、管理接口、事件流和反馈回执时，  
我希望获得与生产契约同源的版本、样例、Mock、错误语义和一致性结果，  
以便在不猜测字段与状态的情况下完成联调并清楚知道距离生产准出还有什么差距。

- AC1：在契约版本有效时，当我准备接入，用户应能够获得完整接口语义、样例与验证环境，并且输入输出可重复验证。
- AC2：在契约不兼容、Mock 漂移或测试失败时，当我继续联调，用户应能够定位差异与责任方，并且失败不会被显示为生产可用。
- AC3：当一致性验证完成后，用户应能够把结果用于后续联合测试与准出，并且沙箱通过和生产准出保持不同结论。

### US-FR6-06 让变化和异常找到正确责任人

作为平台运营和值班负责人，  
在规则、凭证、授权、服务、发布或运行状态发生变化时，  
我希望按风险、对象和责任链把事项送达正确人员并持续升级，  
以便重要变化不因消息分散或无人认领而失控。

- AC1：在通知策略和值班表有效时，当重要事件发生，用户应能够及时获得与其职责相关的事项，并且内容包含对象、影响和下一动作。
- AC2：在渠道失败、无人认领或责任不明时，当事项持续未处理，用户应能够看到升级状态和替代责任链，并且业务事项不会因通知失败自动关闭。
- AC3：当事项处理完成后，用户应能够追溯送达、认领、升级和业务结果，并且通知回执不替代业务证据。

## 2. 产品功能需求

## 功能需求：FR6-FR-01 标准采用与 Project Profile 版本治理

系统应提供标准采用决定和 Project Profile 版本治理能力，支持规则负责人形成、评审、发布、替代和影响分析项目规则，满足 US-FR6-01。

### 功能范围

- 管理外部标准记录、项目采用/不采用/条件采用决定和依据。
- 形成不可变 ProjectProfileVersion，管理术语、主体、治理等级、时空、契约、安全和测试基线。
- 比较版本、展示引用和生成影响任务。

### 关键信息

- standardId/version/status/source、decision、clauseRef、rationale、owner、approvers、effectiveFrom/to、profileVersion、contentHash、引用对象与影响状态。

### 业务规则

- 外部标准状态与项目采用决定分离；标准名称不自动成为系统规则。
- 生效版本不可覆盖；存在冲突或必要决定为 UNKNOWN 时不得标记 EFFECTIVE。
- 被替代版本保留历史引用，受影响契约和测试形成复核任务。

### 验收标准

#### AC1：规则可形成
在依据和责任齐备时，系统应支持形成可审阅的 Profile 版本和采用决定。

#### AC2：信息可理解
查看 Profile 时，系统应展示来源、决定、版本、签认、有效期、差异和引用。

#### AC3：冲突可阻断
出现矛盾决定、缺 Owner 或必要条款未决时，系统应阻断生效并说明责任方。

#### AC4：变化有出口
外部依据变化或版本被替代时，系统应列出受影响对象和复核任务。

#### AC5：结果可复用
有效 Profile 应成为 FR-1～FR-5 契约、规则和测试的固定引用。

## 功能需求：FR6-FR-02 合作方、应用与环境准入

系统应提供合作方、应用和环境准入能力，支持接入负责人管理主体、协议、联系人、应用身份和环境隔离，满足 US-FR6-02。

### 功能范围

- 合作方资质、协议、角色、联系人和值班关系的申请、评审、冻结与退出。
- ApplicationClient 与开发/测试/预生产/生产环境绑定。
- 环境级 Scope、端点、配额、白名单和依赖完整性检查。

### 关键信息

- partnerId、主体角色、协议版本/期限、applicationClientId、environment、owner、purpose、scope、endpointRefs、credentialRefs、quota、status、reasonCode。

### 业务规则

- 主体、协议、应用和环境状态独立；测试身份不能用于生产。
- 协议失效至少阻断新增生产访问；对存量影响按签认策略执行并留证。
- 合作方退出前生成服务、权益、订阅、端点和凭证收口清单。

### 验收标准

#### AC1：准入可办理
系统应支持从主体材料到应用环境形成可追溯的准入关系。

#### AC2：范围可判断
系统应展示应用用途、环境、Scope、端点、凭证、配额和责任联系人。

#### AC3：隔离可守护
跨租户、跨环境、协议无效或用途不符时，系统应阻断相应访问和操作。

#### AC4：异常可修复
材料不足、端点不可达或联系人失效时，系统应提供补正和工单路径。

#### AC5：后续可流转
有效应用环境应可被 FR-1 权益、FR-2 订阅和联合测试固定引用。

## 功能需求：FR6-FR-03 端点、凭证与信任生命周期

系统应提供端点、凭证引用和信任决定治理能力，支持接入安全人员完成注册、验证、轮换、吊销、隔离和到期处置，满足 US-FR6-02/03。

### 功能范围

- 管理主备端点、网络边界、证书/密钥引用、认证方式和健康验证。
- 发起轮换、吊销、隔离、恢复及受影响对象分析。
- 记录外部 CA/KMS/身份源执行结果引用，不接触私钥正文。

### 关键信息

- endpointId、environment、protocolProfile、networkZone、credentialRef、issuer、fingerprint、validFrom/to、status、lastVerifiedAt、rotationPlan、affectedRefs。

### 业务规则

- Secret 只保存引用和必要元数据；私钥、Token 正文不得进入页面、日志、工单或导出。
- 到期、吊销、验签失败和未知信任默认阻断新增高风险操作。
- 恢复必须引用新有效凭证和独立验证，不通过人工改状态完成。

### 验收标准

#### AC1：信任关系可管理
系统应支持登记端点与凭证引用并完成有权验证。

#### AC2：状态可识别
系统应展示有效期、验证结果、主备关系、最近使用和影响对象。

#### AC3：风险可阻断
凭证失效、环境错配或信任未知时，系统应拒绝受影响访问并返回稳定原因码。

#### AC4：轮换不中断审计
轮换或吊销失败时，系统应保留旧新关系、执行结果和安全处置，不覆盖历史。

#### AC5：影响可传播
信任变化应通知受影响订阅、发布和运行域，只由各域决定自身状态。

## 功能需求：FR6-FR-04 身份权限、职责分离与访问复核

系统应提供 RBAC＋ABAC、临时授权、委托、SoD 和访问复核能力，支持安全人员管理自然人和服务账号，满足 US-FR6-03。

### 功能范围

- 管理身份、角色、租户/环境/服务/区域/数据等级 Scope 和有效期。
- 检测编辑、审批、发布、审计等职责冲突，管理有期限例外。
- 发起周期/事件触发的访问复核、收窄与撤销。

### 关键信息

- principalId/type、identitySource、role、resource/action/scope、conditions、grantedBy、validity、lastUsedAt、reviewResult、delegation、SoD conflict/exception。

### 业务规则

- 默认拒绝；页面隐藏不替代服务端鉴权；数据范围与动作权限同时校验。
- 服务账号与自然人账号分开治理，临时授权和例外必须有期限与复核人。
- Break-glass 仅限最小止损，强制事件、通知、审计和事后复核。

### 验收标准

#### AC1：最小权限可授予
系统应支持在固定作用域和期限内授予完成任务所需权限。

#### AC2：权限可解释
系统应展示授权来源、适用条件、最近使用、冲突、到期和复核结果。

#### AC3：越权可阻断
无权限、Scope 不符、跨租户或职责冲突时，系统应拒绝并记录审计。

#### AC4：异常有处置
身份源不可用、授权到期或复核未决时，系统应按失败安全策略限制高风险操作。

#### AC5：收口可证明
收窄、撤销和例外到期后，系统应产生影响与执行证据。

## 功能需求：FR6-FR-05 数据生命周期、Legal Hold 与证据导出

系统应提供数据分类、保留、Legal Hold、受控导出、到期删除和删除验证能力，支持治理与审计人员管理数据和证据全生命周期，满足 US-FR6-04。

### 功能范围

- 版本化管理数据分类、用途、保存期、到期动作与 Owner。
- 预览到期对象、设置/解除 Legal Hold、创建删除任务并验证结果。
- 按用途、范围、脱敏模板、水印和审批导出证据包。

### 关键信息

- classification、purpose、retentionBasis、retentionUntil、holdId/reason/scope、exportPurpose、maskingProfile、deletionJob、verificationEvidence、failureOwner。

### 业务规则

- Legal Hold、法定/合同保留或有效引用存在时不得删除；UNKNOWN 按阻断处理。
- 导出不得超出申请用途与数据范围，敏感内容按 Profile 脱敏并记录接收方。
- 删除失败或部分成功生成安全工单，删除证明不包含已删除敏感正文。

### 验收标准

#### AC1：策略可执行
系统应支持按有效策略识别到期对象并生成影响预览。

#### AC2：保留可守护
存在 Hold 或引用阻断时，系统应拒绝删除并展示依据与 Owner。

#### AC3：导出可控制
系统应按用途、权限、脱敏和审批生成带审计的证据包。

#### AC4：失败可闭环
删除或导出部分失败时，系统应保留逐对象结果并创建责任任务。

#### AC5：结果可核验
完成后应形成可验证的导出清单或删除证明及内容哈希。

## 功能需求：FR6-FR-06 开发者契约、沙箱与一致性验证

系统应提供版本化契约发现、样例、Mock、沙箱工作区和一致性验证能力，支持接入与测试人员完成可重放联调，满足 US-FR6-05。

### 功能范围

- 发布 OpenAPI、AsyncAPI、Schema、原因码、示例、兼容策略和变更记录。
- 申请沙箱、凭证引用、配额和脱敏 fixture；执行认证、Schema、错误、重试、乱序和容量检查。
- 保存 ConformanceRun、Finding、报告版本和有效期。

### 关键信息

- contractId/version/status/contentHash、service/profile refs、compatibility、sample/fixture refs、workspaceId、runId、result、finding、owner、validUntil。

### 业务规则

- Mock、样例与正式契约必须同源校验；契约变化使相关结果 STALE/INVALIDATED。
- 沙箱数据与生产隔离，禁止使用未获授权的生产敏感数据。
- 沙箱通过不等于 FR-4 联合测试或生产准出，页面必须分列。

### 验收标准

#### AC1：契约可发现
系统应支持按服务、环境和版本获取完整有效契约与变更说明。

#### AC2：联调可重放
系统应支持使用固定 fixture 和契约版本执行一致性验证。

#### AC3：漂移可识别
Mock、样例或消费者实现与契约不一致时，系统应报告具体差异和责任方。

#### AC4：异常不假通过
环境不可用、数据未授权或测试未完成时，系统应显示 UNKNOWN/FAILED 而非生产可用。

#### AC5：结果可交接
有效报告应可被 FR-4 测试计划引用，但不直接生成准出结论。

## 功能需求：FR6-FR-07 字典、原因码与平台设置治理

系统应提供跨域字典、原因码和平台设置的版本化治理能力，支持产品、架构和运营统一语义并控制变化影响，满足 US-FR6-01/06。

### 功能范围

- 管理状态展示、原因码、严重度、用户文案、责任方、可重试性和下一动作。
- 管理有明确 Owner 的平台级设置、环境差异、审批和生效范围。
- 检测引用、比较版本、发布和回退。

### 关键信息

- dictionaryCode/version、itemCode、machineMeaning、userMessage、severity、retryable、owner/action、settingCode/valueType/scope、approval、effectiveAt、references。

### 业务规则

- 字典展示语义不得改变领域状态机；同一 code 在同一版本内唯一。
- 生产设置不可原位覆盖，Secret 仅保存引用；无 Owner/依据/影响/回退不得生效。
- 删除或不兼容变更必须经过引用影响分析。

### 验收标准

#### AC1：语义可统一
系统应支持形成可被页面、API、事件和审计引用的版本化字典。

#### AC2：设置可解释
系统应展示设置来源、作用域、环境、版本、审批和生效时间。

#### AC3：冲突可阻断
重复编码、类型不兼容、越权或缺回退时，系统应阻断发布。

#### AC4：变化可响应
字典或设置变化时，系统应列出受影响契约、页面和测试。

#### AC5：结果可回退
生产变更应可创建引用历史良好版本的回退决定并保留审计。

## 功能需求：FR6-FR-08 通知、值班与升级协同

系统应提供通知策略、值班表、送达回执、认领和升级能力，支持运营保障人员把变化和异常交给正确责任人，满足 US-FR6-06。

### 功能范围

- 按对象、风险、环境、事件类型和角色配置通知策略与值班版本。
- 管理站内、组织批准渠道的送达、认领、提醒和升级。
- 将通知与原业务对象、Incident/WorkItem、审批和截止时间关联。

### 关键信息

- policyVersion、eventType、severity、recipientRule、rosterVersion、channelRef、sent/delivered/acknowledgedAt、owner、deadline、escalationLevel、businessRef。

### 业务规则

- 通知送达、人员认领、业务处理和业务关闭是不同事实。
- 渠道失败或无人认领按策略升级；不能因通知失败修改原业务状态。
- 联系方式和通知正文按最小必要原则展示与保留。

### 验收标准

#### AC1：事项可送达
系统应按有效策略和值班表生成通知并关联原业务对象。

#### AC2：责任可识别
系统应展示收件人、送达、认领、截止和升级状态。

#### AC3：升级可执行
超时、渠道失败或无人认领时，系统应进入下一升级层并保留原因。

#### AC4：失败不改业务事实
通知异常时，系统应保留原业务状态并生成可处理的通知故障。

#### AC5：过程可审计
通知、认领、升级和最终业务结果应可按对象追溯。

## 研发需求：FR6-RD-01 不可变 Profile 与采用决定

关联功能需求：FR6-FR-01。

### 需求描述

本需求实现标准记录、采用决定和 Project Profile 的版本化保存、评审、生效、替代和影响传播。当 Profile Owner 提交版本时，系统应根据必要决定、冲突、签认和引用规则生成固定内容哈希；通过审批后创建 EFFECTIVE 版本，不覆盖既有版本，并向受影响域发布只包含事实引用的变化事件。

### 数据与状态

| 对象 | 关键字段 | 读写规则 | 状态 | 外部边界 |
|---|---|---|---|---|
| StandardRecord | source/version/status | 外部事实只读同步或有权录入 | CURRENT/UPCOMING/WITHDRAWN/UNKNOWN | 官方来源核验 |
| StandardAdoptionDecision | clause/decision/rationale | 每项决定不可变 | DRAFT/IN_REVIEW/APPROVED/REJECTED | 合规/项目签认 |
| ProjectProfileVersion | inputRefs/contentHash/effectiveAt | 生效后不可覆盖 | DRAFT/IN_REVIEW/APPROVED/EFFECTIVE/SUPERSEDED/WITHDRAWN | FR-1～FR-5 固定引用 |

### 验收标准

#### AC1：版本固定
在必要决定完整时，当版本获批生效，系统应产生唯一 ProfileVersion 与内容哈希，并满足不可覆盖和审计要求。

#### AC2：冲突阻断
在决定矛盾或必要项 UNKNOWN 时，当提交生效，系统应产生阻断及 Finding，并满足责任人和下一动作可识别。

#### AC3：并发安全
在基于旧 Revision 编辑时，当提交更新，系统应产生冲突 Diff，并满足不覆盖当前版本。

#### AC4：变化传播
在版本被替代时，系统应产生受影响引用清单和变化事件，并满足消费者只读处理。

#### AC5：历史可读
在审计查询时，系统应返回当时有效版本及决定链，并满足历史引用不漂移。

## 研发需求：FR6-RD-02 合作方与应用环境工作流

关联功能需求：FR6-FR-02。

### 需求描述

本需求实现主体、协议、应用和环境的独立工作流及完整性投影。当接入负责人创建或变更应用环境时，系统应校验主体与协议、用途、环境、Scope、端点、凭证和 Owner，保存不可变提交快照并产生审批；批准仅更新准入关系，不推导服务权益或订阅激活。

### 验收标准

#### AC1：关系正确
在主体与协议有效时，当应用环境获批，系统应产生环境隔离的 ApplicationClient 关系，并满足租户和用途绑定。

#### AC2：权限正确
在无权或跨租户请求下，当尝试查看或修改，系统应拒绝并产生审计，不泄露敏感详情。

#### AC3：依赖失效
在协议、联系人或主体状态变化时，系统应更新准入投影和影响任务，不反向改写 FR-1/2 对象。

#### AC4：退出收口
在合作方退出时，系统应生成端点、凭证、权益、订阅和数据收口清单，并满足未完成项不可关闭。

#### AC5：跨域引用
在后续权益/订阅办理时，系统应提供固定应用环境 Revision 和当前有效性，并满足单一事实源要求。

## 研发需求：FR6-RD-03 端点凭证验证与轮换

关联功能需求：FR6-FR-03。

### 需求描述

本需求实现端点注册、凭证引用验证、到期监测、轮换/吊销编排与受影响事实发布。当接入安全人员发起操作时，系统应向有权外部信任服务请求或记录执行结果，只保存引用、指纹、状态与证据；失败、超时和迟到结果不得覆盖更新的操作 Epoch。

### 验收标准

#### AC1：秘密不落地
在任何端点或凭证操作下，系统应只保存 Secret Reference 和必要元数据，并满足页面、日志、事件、导出无私钥/Token 正文。

#### AC2：状态可验证
在外部验证完成时，系统应产生带来源、时点和证据的结果，并满足状态不可手工提升。

#### AC3：幂等与迟到
在重复请求或迟到回执下，系统应返回原结果或记录过期回执，并满足新 Epoch 不被覆盖。

#### AC4：失败安全
在凭证吊销、过期或信任未知时，系统应阻断受影响高风险访问并生成原因码和工单。

#### AC5：影响引用
在信任状态变化时，系统应发布引用事件并满足其他域自主计算影响。

## 研发需求：FR6-RD-04 权限裁决、SoD 与访问复核

关联功能需求：FR6-FR-04。

### 需求描述

本需求实现统一授权裁决、职责冲突检测、临时授权/委托和访问复核。所有服务端读写操作应根据主体、租户、环境、资源、动作、数据分类、条件和有效期裁决；高风险例外需独立批准、期限和缓解措施，前端显示不作为授权依据。

### 验收标准

#### AC1：默认拒绝
在缺少明确允许策略时，当请求访问资源，系统应产生拒绝与最小必要原因，并满足无数据泄露。

#### AC2：作用域生效
在角色相同但租户、环境或数据范围不同时，系统应产生不同裁决，并满足实际 Scope 一致。

#### AC3：SoD 守卫
在编辑、最终审批、发布或审计职责冲突时，系统应阻断或要求有效例外，并满足独立复核。

#### AC4：复核收口
在访问复核完成或到期时，系统应产生保留、收窄、撤销结果和执行证据。

#### AC5：审计完整
在任何授权决定下，系统应记录策略版本、输入、结果和 traceId，并满足可重放。

## 研发需求：FR6-RD-05 生命周期任务与受控导出

关联功能需求：FR6-FR-05。

### 需求描述

本需求实现按策略计算到期、Legal Hold、导出审批、删除任务、逐对象结果和删除验证。系统执行前应固定策略版本、对象清单和引用快照；存在阻断时保持 OPEN，部分失败不得汇总为成功，重试须使用幂等任务标识。

### 验收标准

#### AC1：影响预览
在任务执行前，系统应产生对象、数据量、引用、Hold、权限和风险预览，并满足范围可复核。

#### AC2：Hold 优先
在有效 Hold 或必要引用存在时，系统应产生阻断而非删除，并满足依据和 Owner 可见。

#### AC3：逐对象结果
在批量导出或删除下，系统应保存成功、失败和未知对象清单，并满足部分成功不显示全量完成。

#### AC4：敏感保护
在证据导出时，系统应按用途和脱敏 Profile 生成结果，并满足接收方、水印和访问审计。

#### AC5：证明可核验
在任务完成时，系统应产生清单、内容哈希与验证证据，并满足不含已删除敏感正文。

## 研发需求：FR6-RD-06 契约注册、Mock 与一致性运行

关联功能需求：FR6-FR-06。

### 需求描述

本需求实现契约制品注册、版本/哈希、Mock 和 fixture 引用、沙箱工作区及 ConformanceRun。当契约发布或替代时，系统应验证制品一致性、计算兼容性、使受影响运行 STALE/INVALIDATED，并禁止未批准契约进入生产接入。

### 验收标准

#### AC1：制品一致
在契约发布时，系统应校验 OpenAPI/AsyncAPI/Schema/原因码及样例引用，并满足版本、哈希和状态一致。

#### AC2：运行可重放
在固定契约与 fixture 下，当重复执行，系统应产生可比较结果并满足输入版本可追溯。

#### AC3：漂移失效
在契约变化时，系统应使受影响 Mock/报告失效并生成重测任务，不静默沿用旧结论。

#### AC4：环境隔离
在沙箱运行时，系统应限制凭证、配额和数据范围，并满足生产数据/凭证不可混用。

#### AC5：结论边界
在一致性通过时，系统应产生报告引用，但不得写入 FR-4 生产准出成功。

## 研发需求：FR6-RD-07 字典设置版本与依赖影响

关联功能需求：FR6-FR-07。

### 需求描述

本需求实现字典和平台设置的不可变版本、Schema 校验、作用域解析、影响分析与回退。生产版本变更应固定 Diff、审批、生效时间、依赖和回退目标；消费者通过固定版本或变化事件刷新，不读取未审批草稿。

### 验收标准

#### AC1：版本不可覆盖
在生产字典或设置修改时，系统应创建后继版本并满足旧引用可读取。

#### AC2：类型和唯一性
在编码重复、值类型错误或作用域冲突时，系统应产生阻断并满足原因可定位。

#### AC3：权限与秘密
在无权访问或 Secret 类型设置下，系统应返回脱敏引用并满足正文不泄露。

#### AC4：影响与失效
在不兼容变化下，系统应生成依赖清单和重测/迁移任务，并满足消费者不被静默破坏。

#### AC5：回退可审计
在回退时，系统应创建新的决定引用历史良好版本，并满足时间线完整。

## 研发需求：FR6-RD-08 通知投递、认领与升级

关联功能需求：FR6-FR-08。

### 需求描述

本需求实现事件到通知的规则匹配、接收人解析、渠道投递、送达/认领和升级。当业务事件进入时，系统应固定策略和值班版本，生成幂等通知；渠道失败、超时或无人认领触发升级，不改变原业务对象的事实状态。

在值班与责任规则有效时，系统应产生确定接收人及替补链，并满足租户/环境范围正确。

#### AC3：送达与业务分离
在通知送达或认领时，系统应只更新通知事实，并满足原业务状态不被自动完成。

#### AC4：失败升级
在渠道失败、超时或无人认领时，系统应产生升级记录和下一层通知，并满足原因可追溯。

在查询对象时间线时，系统应返回策略、值班、投递、认领、升级和业务结果引用。

标准与 Profile-PG02 标准采用与项目基线工作台

- 支持标准事实、项目采用决定和 Project Profile 版本管理。
- 支持条款映射、版本 Diff、引用影响和会签。

### 5. 验收结果
- 完整基线通过会签后应生成不可变版本并可被其他域引用。
- 来源失效、冲突或权限不足时应明确阻断，不产生虚假有效版本。

- 新增应用时必须选择主体、用途和环境；生产环境显示更严格前置项。
- 冻结/退出先展示权益、订阅、端点和凭证影响，提交后创建控制事项而非直接宣称完成。
- 协议临期显示到期日、Owner 和续签入口。

### 4. 业务规则
- 测试与生产身份、凭证、Endpoint 和数据隔离。
- 主体/协议/应用/环境状态独立；无有效协议不可新增生产权限。
- 六态和权限按当前租户、环境及角色计算。

### 5. 验收结果
- 有效准入应产生可供 FR-1/2 固定引用的应用环境版本。
- 材料不足、跨环境复用或退出清单未完成时应阻断相应动作。

## 研发需求名称

端点与信任-PG07-C 端点、凭证和轮换子工作台

## 描述

作为接入安全人员，在管理云云端点和信任关系时，我希望可验证地注册、轮换、吊销和隔离凭证引用，以便降低过期、泄露和环境混用风险。

关联功能需求：FR6-FR-03。

## 验收标准

### 1. 功能范围
- 支持主备端点、网络区、协议 Profile 和凭证引用管理。
- 支持连接/信任验证、到期提醒、轮换、吊销、隔离和恢复复核。
- 支持逐目标执行结果与影响对象查看。

### 2. 页面内容
- 查询条件：合作方、应用、环境、端点、凭证状态、到期范围、健康。
- 表格字段：Endpoint、环境、主备、协议、凭证指纹摘要、签发方、有效期、验证状态、最近验证、影响数。
- 页面操作：`注册端点`、`验证连接`、`发起轮换`、`吊销`、`隔离`、`请求恢复复核`。
- 敏感字段：只显示 Secret Reference 和脱敏指纹，不显示秘密正文。

### 3. 交互规则
- 高风险操作先展示作用域、影响、执行目标和恢复条件。
- 执行中展示逐目标状态；请求已接受、执行成功和恢复验证分开展示。
- 迟到回执保留在时间线，不覆盖更高 operationEpoch。

### 4. 业务规则
- 仅接入安全 Owner 可发起，吊销/恢复需职责分离。
- 信任未知、过期或环境错配默认阻断新增高风险访问。
- 页面六态中 Partial 必须列出成功、失败和未知目标。

### 5. 验收结果
- 合法轮换应保留新旧引用、执行结果和审计，不中断事实追溯。
- 私钥/Token 不得出现在页面、日志、导出或错误信息中。

## 研发需求名称

权限治理-PG23 身份、授权与访问复核工作台

## 描述

作为安全管理员，在人员和服务账号持续变化时，我希望管理最小权限、职责分离和访问复核，以便保证平台访问与当前职责一致。

关联功能需求：FR6-FR-04。

## 验收标准

### 1. 功能范围
- 支持身份、角色、ABAC Scope、临时授权、委托与 SoD 例外。
- 支持访问复核、收窄、撤销和到期处理。
- 支持授权决定与最近使用审计。

### 2. 页面内容
- 查询条件：主体类型、身份、租户、角色、环境、资源、动作、数据分类、状态、到期。
- 表格字段：身份、角色、Scope、来源、条件、有效期、最近使用、冲突、复核结果。
- 页面操作：`申请授权`、`审批`、`收窄`、`撤销`、`委托`、`发起访问复核`。
- 详情页签：权限、策略解释、SoD、历史决定、访问记录、审计。

### 3. 交互规则
- 选择角色后实时显示实际 Scope、冲突和需要的会签，不以角色名称隐藏条件。
- 撤销/收窄展示受影响任务和会话；提交后显示执行证据。
- 无权用户看到缺失 Scope 和申请入口，不显示敏感权限详情。

### 4. 业务规则
- 默认拒绝；自然人和服务账号分开；临时/委托/例外必须有期限。
- 编辑、最终审批、发布和审计冲突按 SoD 规则阻断。
- 页面可见性不替代后端授权，六态均需实现。

### 5. 验收结果
- 合法授权应在限定范围和期限内生效并可解释。
- 越权、跨租户、冲突或过期请求应被拒绝并留下审计。

## 研发需求名称

数据生命周期-PG23-L 保留、Hold、导出与删除子工作台

## 描述

作为数据治理负责人，在数据和证据达到保留节点或需要受控导出时，我希望先核对用途、引用和保留阻断再执行，以便兼顾审计和最小保存。

关联功能需求：FR6-FR-05。

## 验收标准

### 1. 功能范围
- 支持保留策略、到期预览、Legal Hold、受控导出和删除任务。
- 支持逐对象结果、失败工单、删除验证和证明。
- 支持导出脱敏、水印、用途和接收方审计。

### 2. 页面内容
- 查询条件：数据分类、对象类型、用途、Owner、到期范围、Hold、任务状态。
- 表格字段：对象/数量、策略版本、保留依据、到期日、Hold、引用、风险、任务结果。
- 页面操作：`预览到期对象`、`申请Hold`、`解除Hold`、`申请导出`、`执行删除`、`验证删除`。
- 详情区：对象清单、阻断、审批、逐项执行、证据和工单。

### 3. 交互规则
- 执行前固定对象快照并展示成功/阻断/未知数量。

### 4. 业务规则
- 有效 Hold、法定/合同保留、引用未知或权限不足时禁止删除。
- 敏感证据导出必须有用途、审批、脱敏和到期。
- 删除证明不得包含被删除正文；普通管理员不能修改审计结果。

### 5. 验收结果
- 合法任务完成后应产生逐对象结果与可核验证明。
- Hold 冲突、部分失败或无权导出时应阻断或保持 OPEN，不产生假成功。

- 重要事项应按有效责任链送达并可追溯到业务对象。
- 重复事件、渠道失败或责任不明时应去重/升级并保持业务事项开放。

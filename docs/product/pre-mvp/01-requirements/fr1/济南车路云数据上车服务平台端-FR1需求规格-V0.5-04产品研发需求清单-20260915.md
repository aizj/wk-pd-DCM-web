# FR-1 产品研发需求清单

> 文档版本：V0.5  
> 本文用于前端、交互与页面测试拆单。每项固定包含功能范围、页面内容、交互规则、业务规则、验收结果；后端状态机、事件和权限实现见 V0.5-03。

---

## 研发需求名称

【治理中心】-【FR1-P01 标准与 Project Profile 台账】

## 描述

作为标准/Profile 管理员，在标准发布、实施或项目采用决定变化时，我希望统一核验来源、维护条款映射并冻结项目规则版本，以便服务、车型能力与测试团队使用同一基线。

关联功能需求：FR-01

### 1. 功能范围

- 提供标准记录列表、来源核验、条款映射、项目采用决定和 Profile 版本详情；
- 支持登记、补证、比较、送审、冻结、替代和影响查看；
- 支持从服务、兼容阻断项和迁移任务反向进入对应规则；
- 不在本页面维护具体协议字段、算法参数或测试用例正文。

### 2. 页面内容

- 列表区：标准编号/名称、发布机构、外部状态、发布/实施日、项目采用状态、核验状态、Owner、更新时间；
- 详情摘要：来源链接/文件摘要、核验时间、适用条款、项目采用范围、偏差/扩展、决定人和期限；
- Profile 版本区：版本号、状态、内容哈希、未决项、替代关系、引用数量和生效时间；
- 差异与影响区：新旧条款、项目决定变化、受影响服务/能力/评估/测试；
- 状态呈现：加载中、空记录、无来源、部分可核验、无权限、数据冲突和服务异常；
- 审计入口：查看创建、核验、采用、冻结、导出和替代记录。

### 3. 交互规则

- “登记标准”按基础信息 → 来源 → 条款 → 项目采用建议分步保存草稿；
- “核验”需明确核验结论、时间和证据，无法确认时选择无法核验并分配 Owner；
- “冻结 Profile”前展示未决项、破坏性变化和影响摘要，阻断项未清零时不可确认；
- 比较任意两个 Profile 版本时，按新增、变化、删除、未决四类展示；
- 从阻断项进入时自动定位对应条款，但返回后保留原业务上下文；
- 无权操作显示原因和申请权限/联系 Owner 入口，不只隐藏操作。

### 4. 业务规则

- 外部状态和项目采用状态分栏，`UPCOMING` 不使用当前有效的成功色；
- 来源不可核验时显示 `UNVERIFIABLE`，不得留空或显示“已核验”；
- 已冻结 Profile 只读，变化只能创建新版本；
- 破坏性变化必须有关联迁移方案或明确发布阻断；
- 所有规则可追溯到来源条款和项目决定。

### 5. 验收结果

- 能完成一条标准从登记、核验、项目采用到 Profile 冻结的闭环；
- 能识别已发布未实施、来源不可核验和项目未采用三类不同状态；
- 能查看两个 Profile 的差异及受影响对象，未知影响单独展示；
- 已冻结内容无法被原位修改，历史引用仍可打开；
- 权限、空态、部分失败和服务异常均有明确反馈与退出路径。

## 研发需求名称

【数据授权】-【FR1-P02 数据提供权详情】

## 描述

作为数据授权经办人与有权签认人，在对外提供数据或既有依据变化时，我希望结构化记录范围、证据、决定及下游影响，以便后续门禁可以计算并安全执行。

关联功能需求：FR-02、FR-03、FR-04

### 1. 功能范围

- 提供数据提供权列表、草稿创建、送审、审批、补证、续期、收窄、暂停和撤销；
- 支持范围、条件、证据、评估、影响、审批、审计七类信息查看；
- 嵌入提供权逐维匹配结果与可允许交集；
- 支持进入影响中心和发起紧急停发请求；
- 不以附件上传自动生成有效授权结论。

### 2. 页面内容

- 页头：Authority ID、Revision、生命周期、决定结果、核验状态、有效期、Owner；
- 范围摘要：提供/运营/决定/接收主体、用途、数据/服务/字段、Coverage、环境、时间和再提供边界；
- 条件区：允许、禁止、精度、留存、出域、派生、撤销和退出义务；
- 证据区：依据类型、文号、文件摘要、内容哈希、签认人、签认时间、有效期和访问级别；
- 匹配区：每个维度的规则、事实、证据、结果、原因、Owner、下一动作及允许交集；
- 影响区：数据产品、服务、Offering、权益、订阅/运行对象和未知依赖；
- 状态呈现：草稿、审批中、退回、有效、临期、暂停、到期、撤销、不可核验、冲突和无权限。

### 3. 交互规则

- 新建过程按主体 → 用途与范围 → 条件 → 证据 → 影响预览 → 提交分步完成；
- 提交前逐项定位缺失的结构化信息，附件存在不取消缺项提示；
- 审批区同时展示当前范围、上一 Revision 差异、证据有效性和预估下游影响；
- 收窄/撤销采用二次确认，必须填写原因、生效时点并预览最小影响范围；
- 影响包含 UNKNOWN 时以阻断色和单独数量展示，并可创建核查任务；
- 敏感附件查看或导出时先校验权限，成功后显示水印与访问留痕提示。

### 4. 业务规则

- 经办人与最终签认人分离；高风险范围需安全/合规会签；
- 空范围不代表全部，自由文本不能替代主体、用途、字段、区域和期限；
- 已生效 Revision 只读，续期或范围变化创建新 Revision；
- `INCONCLUSIVE` 与 `DENY` 均阻断生产，但原因和修复方式必须不同；
- 撤销不删除历史，恢复必须基于新的有效依据。

### 5. 验收结果

- 能完成有效依据的创建、送审、签认、生效和历史追溯；
- 关键范围缺失、证据失效、职责冲突时均被阻断并显示责任人；
- 能逐维查看 ALLOW、ALLOW_WITH_CONDITIONS、DENY、INCONCLUSIVE 的事实和依据；
- 收窄/撤销前能查看差异和已知/未知影响，执行后可跟踪回执；
- 无权限、并发冲突、附件不可用和影响计算失败均有可恢复路径。

## 研发需求名称

【数据产品】-【FR1-P03 数据产品与质量工作台】

## 描述

作为数据产品与质量负责人，在交通数据需要支撑上车服务时，我希望管理来源、语义、血缘、质量策略和备选来源，以便服务输入可追溯并按已批准边界降级。

关联功能需求：FR-05

### 1. 功能范围

- 提供 DataProduct 列表、版本详情、创建、校验、送审、发布、弃用和失效处理；
- 管理来源依据、Schema/语义、字段级血缘、分类、QualityPolicy 和备源；
- 展示数据产品与 ServiceVersion 的引用关系；
- 支持质量规则回放结果、实时质量摘要和降级/恢复动作查看；
- 不在本页面直接修改上游源系统或运行采集配置。

### 2. 页面内容

- 页头：数据产品编码、版本、类型、状态、Owner、Schema 哈希、更新时间；
- 来源区：源系统、权威等级、获取依据、适用环境和有效期；
- 契约区：字段、类型、单位、时间/空间语义、示例、兼容说明；
- 血缘区：原始来源、处理步骤、算法/地图版本、派生路径和断点；
- 质量区：指标、单位、窗口、测量点、阈值依据、UNKNOWN 动作、失败/恢复动作；
- 备源区：候选来源、优先级、授权、语义、质量和可切换结论；
- 引用与状态区：关联服务、实时质量摘要、临期/失效影响、加载/空/部分失败状态。

### 3. 交互规则

- 创建版本按来源 → 契约 → 血缘 → 分类 → 质量 → 备源 → 引用影响组织；
- 选择任一输出字段可展开来源与处理链，并定位缺失环节；
- 运行校验后按阻断、警告、建议分组，阻断项提供 Owner 与处理入口；
- 配置备源时同时展示其授权、语义和质量结论，任一不通过不可设为候选；
- 质量实时事实与策略版本分区展示，防止用户误以为调整实时值会改变策略；
- 已发布版本只读，“变更”操作进入新版本并预填差异。

### 4. 业务规则

- 来源获取依据与对外提供依据分别展示和校验；
- Schema、语义或关键加工发生不兼容变化时必须新建版本；
- QualityPolicy 必须具有单位、窗口、测量位置、阈值依据和失败/恢复动作；
- UNKNOWN 不计合格，备源不能绕过授权、语义和质量要求；
- 已被引用的发布版本不得物理删除。

### 5. 验收结果

- 能发布一项来源、契约、血缘、分类和质量均完整的数据产品版本；
- 任一输出字段可追溯到来源、处理和依据；
- 血缘断点、无依据阈值和未授权备源均能被阻断；
- 质量下降时能显示受影响服务、降级动作和恢复条件；
- 页面在大字段量、部分校验失败、无权限和历史只读情况下仍可明确操作。

## 研发需求名称

【服务产品】-【FR1-P04 服务产品工作台】

## 描述

作为服务产品经理，在创建信号灯、绿波、拥堵、VRU 或异常停车等上车服务时，我希望完整定义并验证服务契约，以便 OEM、数据、测试和运营围绕同一版本协同。

关联功能需求：FR-06

### 1. 功能范围

- 提供 ServiceProduct 列表、ServiceVersion 创建、比较、校验、送审、发布和查看；
- 管理 13 类最小服务契约及其版本引用；
- 支持场景、输出、资格、车型要求、依赖和 DVP&R 分项配置；
- 展示授权覆盖、能力样本、依赖图和治理等级门禁；
- 不承担 Offering 开放策略、OEM 能力事实和运行参数实例配置。

### 2. 页面内容

- 左侧契约导航：身份/JTBD、治理等级、输入、场景、输出、Coverage、计算、交付、质量、车型要求、反馈、安全/审计、依赖/迁移、DVP&R；
- 中部工作区：当前内容、来源对象、引用版本、Owner 和变更说明；
- 右侧检查区：完整度、阻断、警告、建议、责任人和修复入口；
- 底部证据区：与上一版本差异、依赖图、提供权覆盖、兼容样本、测试证据和审批记录；
- 页头：服务编码、版本、治理等级、状态、Owner、内容哈希、发布日期；
- 状态呈现：草稿、校验中、评审中、批准、发布、弃用、退役、部分数据失败和无权限。

### 3. 交互规则

- 新建服务先确认稳定 ServiceProduct 身份，再创建 ServiceVersion 草稿；
- 契约导航显示每一类完整度和阻断数量，选择阻断项定位到缺失内容；
- 引用数据、规则、输出或能力要求时显示其版本、状态、有效期和 Owner；
- “运行校验”给出确定性结果；依赖变化后显示上次结果已失效并要求重跑；
- “送审/发布”前展示 13 类契约摘要、提供权结论、治理等级会签和 DVP&R 状态；
- 已发布版本只读，变更时创建新版本并展示差异与迁移要求。

### 4. 业务规则

- Service、Scene、Output、Delivery 和 Offering 分开管理；
- 输出必须有首次、更新、撤销、失效和原因语义；
- 信息、建议、预警、算法消费使用不同治理等级门禁；
- 关键依赖 UNKNOWN、数据提供权 INCONCLUSIVE 或 DVP&R 不完整时不得发布；
- 禁用用途和责任边界不得被宣传文案弱化。

### 5. 验收结果

- 能完成一个代表性上车服务从草稿、校验、评审到不可变发布版本；
- 13 类契约的缺失、冲突和责任人可被准确定位；
- 依赖循环、输出撤销缺失和治理等级证据不足均被阻断；
- 发布后内容不可原位修改，新版本具备差异和迁移关系；
- 加载、空数据、部分引用失败、版本失效和无权限状态均表达清楚。

## 研发需求名称

【服务运营】-【FR1-P05 Service Offering 管理】

## 描述

作为服务运营负责人，在已发布服务面向不同 OEM、用途、区域和环境开放时，我希望独立管理供给范围与申请条件，以便目录可见性不被误认为已经获权。

关联功能需求：FR-03、FR-07

### 1. 功能范围

- 提供 Offering 列表、创建、校验、送审、上架、暂停、弃用、下架和新版本；
- 管理可见对象、申请资格、用途、Coverage、环境、通道、期限、数量和支持边界；
- 展示 ServiceVersion、ProvisionAuthority、协议模板和能力要求引用；
- 预览不同 OEM/应用条件下的可见、可申请和阻断结果；
- 不承载价格、折扣、账单或已经授予的权益范围。

### 2. 页面内容

- 列表区：Offering 编码/版本、服务、目标对象、用途、区域、环境、开放期、状态、Owner；
- 配置区：目录可见、申请资格、允许/禁止用途、Coverage、通道、期限、配额、速率、支持窗口；
- 依据区：ServiceVersion、ProjectProfile、ProvisionAuthority、能力要求、协议模板和审批引用；
- 预检区：各维度范围、允许交集、越界、条件、原因和修复入口；
- 存量影响区：现有权益、订阅、OEM 和暂停/下架后的处置建议；
- 状态呈现：草稿、评审中、上架、暂停、弃用、下架、依据临期、不可核验和无权限。

### 3. 交互规则

- 创建时先选择 ServiceVersion，再配置对象/用途/区域/环境，系统持续显示允许交集；
- 目录预览可切换模拟 OEM、应用类别和环境，不显示不属于该对象的信息；
- 上架前展示 ServiceVersion 状态、授权结论、能力要求、协议和依赖有效性；
- 范围越界时定位维度，并允许收窄到交集或发起补充依据，不允许一键忽略；
- 暂停/下架前区分“停止新申请”与“影响存量权益”，并进入影响预览；
- 已上架范围变化时创建新版本，不在原版本上直接保存。

### 4. 业务规则

- ServiceVersion 定义服务，Offering 定义当前开放，二者状态相互独立；
- 可见不等于可申请，可申请不等于最终获权；
- Offering 必须是服务契约与有效 ProvisionAuthority 的子集；
- 暂停 Offering 默认停止新增申请，不自动撤销存量权益；
- 同一 ServiceVersion 可有多个不同对象/区域/用途的 Offering，但证据分别可追溯。

### 5. 验收结果

- 能创建并上架一个只对指定 OEM、用途、区域和环境开放的 Offering；
- 不同模拟对象只能看到符合可见规则的结果，且不显示“已开通”；
- 超出授权、服务未发布和关键依赖临期均能阻断上架；
- 暂停/下架能区分新增影响和存量影响，并提供后续处置入口；
- 版本变化、并发冲突、部分预检失败和无权限均有明确反馈。

## 研发需求名称

【服务运营】-【FR1-P06 生命周期与迁移】

## 描述

作为服务产品与运营负责人，在服务版本升级、弃用或退役时，我希望按存量关系组织迁移和退出，以便 OEM 有明确兼容窗口且不会静默失去服务。

关联功能需求：FR-08、FR-04

### 1. 功能范围

- 提供弃用发起、替代版本、迁移计划、批次、提醒、例外和退役检查；
- 展示 Offering、权益、订阅、OEM、运行对象和未知依赖；
- 支持迁移状态跟踪、失败升级、强制退出决定和证据归档；
- 支持从 ServiceVersion、影响中心和待办进入；
- 不直接执行车端升级或运行节点变更。

### 2. 页面内容

- 概览：原版本、替代版本、弃用时间、停止新申请时间、迁移截止、兼容窗口；
- 迁移漏斗：未开始、已通知、处理中、已迁移、已终止、获批例外、失败、未知；
- 对象清单：OEM、Offering、权益、订阅/运行对象、Owner、期限、状态和证据；
- 例外区：原因、批准人、适用范围、有效期、缓解措施和退出安排；
- 退役检查：未处置依赖、开放问题、强制退出依据和最终证据；
- 状态呈现：计划中、进行中、阻断、部分完成、已完成、已取消、数据延迟和无权限。

### 3. 交互规则

- 发起弃用必须选择替代版本或明确“无替代”并填写终止计划；
- 创建迁移计划后可按 OEM/Offering/风险分批，但每个对象保留独立结论；
- 选择漏斗阶段联动过滤对象清单，UNKNOWN 始终单独显示；
- 例外审批采用有效期和退出安排必填，过期自动回到待处置；
- “执行退役”前展开所有未处置对象，存在一个硬阻断即不可确认；
- 授权紧急撤销时切换到紧急收口路径，不等待迁移窗口。

### 4. 业务规则

- DEPRECATED 与 RETIRED 分离；弃用默认停止新 Offering/权益引用；
- 通知送达不等于迁移完成；
- 退役前每个存量对象必须有迁移、终止或有权例外结论；
- 例外必须有范围、期限、批准人、缓解和退出计划；
- 历史服务版本和迁移证据长期可追溯。

### 5. 验收结果

- 能为服务版本创建替代关系、兼容窗口和分批迁移计划；
- 能从漏斗定位未处置、失败、例外和未知对象；
- 存在未处置活跃关系时退役操作被阻断；
- 紧急撤权能转入最小范围收口而非继续等待；
- 部分数据失败、回执超时和无权限状态均不会被误显示为完成。

- 对象区：类型、对象版本、作用域、建议动作、Owner、截止、回执、失败原因和证据；
- 任务区：续期、迁移、停发、核查、恢复、升级及跨 FR 关联；
- 状态呈现：计算中、可执行、存在 UNKNOWN、部分收口、已收口、计算失败、数据延迟和无权限。

### 3. 交互规则

- 从任何高风险动作进入时保留触发上下文，并先展示最近一次冻结快照；
- “重算”生成新快照，不覆盖原快照；执行动作引用明确快照版本；
- 统计卡与对象清单联动过滤，UNKNOWN 不并入未影响或成功；
- 批量创建任务前预览每个对象的动作与 Owner，允许移除非必处置项但需填写理由；
- 紧急停发需展示最小作用域、生效时间、下游接收方和失败安全策略；
- 只有所有必处置对象成功或取得有权例外后才开放“确认收口”。

### 4. 业务规则

- 影响快照固定触发版本、依赖版本、计算时点和内容哈希；
- UNKNOWN 不得计为零影响或完成；
- 通知送达不等于处置成功，必须接收业务回执；
- 紧急执行人不能单独批准恢复；
- 导出遵循数据分类、脱敏、水印和审计规则。

### 5. 验收结果

- 能对授权收窄生成固定影响快照并追到 Offering、权益和后续运行对象；
- 重算形成新快照，旧快照及当时处置证据不被覆盖；
- UNKNOWN、失败、超时和例外分别统计并可定位 Owner；
- 未取得全部必要回执时不能标记已收口；
- 能把精确停发/恢复任务交给后续 FR 并展示回执，部分失败和无权限状态清楚。

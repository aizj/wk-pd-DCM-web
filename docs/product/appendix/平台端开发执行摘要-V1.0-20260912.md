> 权威依据：[平台端功能规划与架构核验报告-V1.8-实证收口版-20260912.md](平台端功能规划与架构核验报告-V1.8-实证收口版-20260912.md)

## 1. 使用方式与结论

本摘要用于后台端开发开工、任务拆分、设计评审、接口评审和测试验收。它从V1.8抽取必须执行的决定、页面、状态、接口、跨端不变量、影响面和门禁；V1.8仍是完整依据库，历史V1.0—V1.7文档不得覆盖本摘要的现行口径。

本项目的核心约束是：**移动端源码、依赖、构建配置、页面、入口、用户操作路径、业务指令名称、任务/告警/事件主状态、现场反馈交互和本地数据访问均不改；本期只建设平台端Web及服务端，并冻结可供未来外部接入使用的兼容API、事件和投影Schema。当前移动端仍是localStorage/MockWS演示运行，运行时跨端联动不计入本期交付。**

本摘要可以直接指导后台详细设计和研发拆分，但不等于平台已经开发完成，也不等于真实接口、直控授权、性能、安全、信创和现场验收已经通过。

### 1.1 先记住的十条硬规则

1. 一个领域服务、一个业务ID、一个状态机、两类客户端视图。
2. 普通指令预检通过后，服务端事务内同时创建`Command(sending)`、`Task(pending_receipt)`和`OutboxMessage`，再异步调用主体单位。
3. 普通指令五类保持为：减速、靠边停车、启动行驶、快速驶离、远程接管；直控仅急停、急停恢复。
4. 任务状态和主体单位回执状态必须分开存储、分开显示、分别验收。
5. 移动端直控继续使用现有二态结果`accepted/rejected`和三种意图状态；平台内部才使用传输状态、业务结果、核实状态和`safetyHold`。
6. 网关超时不能直接判定业务拒绝，也不能重复调用网关试探结果；必须进入技术挂起和人工核实。
7. 告警只有“任务完成+成功反馈”才能自动归档；部分、失败、异常和撤回均保留待跟进。
8. 非成功反馈必须有`assigneeId`、`nextAction`、`dueAt`、`dueAtSource`和逾期升级，不允许静默堆积。
9. 生产不使用localStorage、Mock、静态HTML或车型默认企业映射作为业务事实源。
10. 直控生产入口、条件型合规能力和企业门户必须以真实授权、责任协议、数据源和契约证据为门禁。

## 3. 冻结决策

### 3.1 移动端不改的准确含义

本期不允许修改移动端源码、依赖、构建配置、页面、入口、按钮路径、业务状态、交互或localStorage/Mock调用；只建设平台端Web、服务端领域服务、数据库、外部系统适配、兼容API/事件和联调夹具。由于当前移动端未发现可用的HTTP/SSE/WebSocket生产契约，平台端不能单方宣称已完成运行时联动；未来若要接入，必须另立外部接入事项并单独验收。

禁止以下做法：

- 在移动端和后台分别写入两套指令、任务或告警事实；
- 生产接口失败时回落到Mock或本地种子；
- 用浏览器缓存推进任务终态、反馈成功、告警归档或直控授权；
- 将平台技术状态泄漏为移动端新的“未知/待核实”业务枚举；
- 用页面中文文案、姓名拼接或全角标点作为身份关联键。

### 3.2 状态基线

| 对象 | 现行状态 | 开发要求 |
|---|---|---|
| 普通指令回执 | `sending → accepted → executing → succeeded/failed`；发送中/已接收可撤回 | 回执表达主体单位链路和执行过程，不替代任务状态 |
| 任务 | `pending_receipt → received → executing → completed/abnormal`；前置阶段可撤回 | 任务在指令原子创建时生成，必须关联唯一`commandId` |
| 告警 | `pending → resolved` | `unread`、已响应和已归档分别记录；成功反馈才自动归档 |
| 应急事件 | `reported/handling/closed` | 可只上报；区域任务是可选后续动作，人工闭环不改写关联任务 |
| 直控意图 | `ready_for_stop/submitting/stop_requested` | 移动端保持现有三态；平台技术挂起独立于意图状态 |
| 直控业务结果 | `accepted/rejected` | 网关超时不得伪造成明确结果；平台通过核实后映射既有投影 |
| WorkItem | `open → claimed → resolved` | 非成功反馈、技术核实、通道故障必须有责任人和下一动作 |

### 3.3 状态归属不变量

1. `Command`服务推进指令回执；`Task`服务推进任务；`Alert`服务推进告警；`Incident`服务推进事件；页面不能越权改写其他对象主状态。
2. 回执状态、任务状态、告警状态、事件状态和技术状态不能共用一个字段。
3. 状态更新必须携带`stateVersion`并使用CAS/行版本；冲突返回409和服务端最新版本。
4. 所有历史记录绑定`schemaVersion`、`dictionaryVersion`、`stateMachineVersion`和规则快照。

## 6. 核心流程（研发必须按此实现）

### 6.1 普通指令

```text
平台端发起（未来外部接入时可复用同一契约）
  → 服务端鉴权、数据范围、能力、实时状态、在途冲突和幂等预检
  → 一个事务写入 Command(sending) + Task(pending_receipt) + OutboxMessage
  → 返回 HTTP 201 + commandId/taskId（只代表已创建，不代表主体单位受理）
  → Outbox异步调用主体单位
  → 回调按messageId/sequence/stateVersion幂等对账
  → 回执推进，任务独立推进
  → 完成/异常/撤回终态 + 审计 + 必要告警/WorkItem
```

失败出口：

- 业务拒绝：回执`failed`，任务`abnormal`，按现有告警类型进入处置；
- 通信/超时：不冒充业务拒绝，记录系统异常和人工联系事项；
- 重复请求：同一`clientRequestId`返回原业务ID和已知结果，不重复调用主体单位；
- 并发冲突：返回409、当前状态版本和允许动作，不覆盖他人结果；
- 撤回：仅发送中/已接收允许；执行中不得伪造撤回成功。

### 6.2 直控急停/恢复

```text
选择车辆
  → 服务端校验独立直控权限、辖区/项目授权、责任协议、车辆能力、数据新鲜度、互斥和强认证
  → 记录不可变AuthoritySnapshot + DirectControlAttempt
  → 调用网关一次
  → 明确受理/拒绝：平台记录并冻结可供未来移动端接入的accepted/rejected投影
  → 超时/网络异常：transport=timeout/network_error、businessResult=null、verification=pending、safetyHold=true
  → 冻结冲突动作，生成VerificationCase和WorkItem，禁止重复网关调用
  → 不同人员核实已执行/未执行/无法核实
  → 平台冻结移动端既有意图投影；无法核实则保持挂起并升级，未来接入时再消费投影
```

直控必须有物理分隔、非默认展开、不预选动作、不设置快捷键、不进入批量工具条。平台显示技术状态和核实进度，移动端不新增业务状态。

### 6.3 告警—任务—反馈—归档

1. 告警生成后进入`pending`，记录来源和去重规则版本。
2. 响应、认领、分派、升级属于WorkItem/治理动作，不改变告警主状态。
3. 关联任务完成且反馈为成功时，服务端自动将告警归档。
4. 部分、失败、异常终止、撤回或反馈缺失时，告警保持可跟进；生成或维持唯一WorkItem。
5. WorkItem必须有负责人、下一动作和到期时间；逾期触发升级，关闭必须记录风险解除或后续事项承接依据。

### 6.4 应急事件与区域批次

1. 事故、故障、道路障碍先保存事件；无车辆或无区域锚点时允许只上报。
2. 用户明确启用区域处置后，对每辆候选车独立执行预检。
3. 每辆车通过预检后复用普通指令事务生成指令、任务和Outbox；批次仅做汇总。
4. 成功、跳过、失败逐车返回；部分失败不回滚事件和已创建任务。
5. 事件人工闭环必须说明依据；不自动修改仍在执行的任务。

### 6.5 值班与交接

| 模式 | 最小交付 | 不做什么 |
|---|---|---|
| 单席试运行 | 在途事项快照、未完成责任人、导出、下次登录续办 | 不建设复杂排班、逐级分派、双人交接表单 |
| 多席/轮班 | 队列认领、分派/转派、升级、交接双方确认、临时权限到期 | 不预置实际组织不存在的多级层级 |

不能仅按人数取消责任留痕；2至3人只要存在跨班或安全关键操作，仍需快照、责任人和续办机制。交班动作不能自动关闭源告警、任务或事件。

## 7. API与事件最小契约

### 7.1 接口规则

| 场景 | HTTP语义 | 强制字段/行为 |
|---|---|---|
| 创建普通指令 | `201 Created` | `commandId/taskId/correlationId/stateVersion`；创建成功不等于受理 |
| 创建直控尝试 | `201 Created`或按平台现行契约返回 | `attemptId/authoritySnapshotId`；网关只调用一次 |
| 批量区域处置/导出/配置发布 | `202 Accepted` | 返回`operationId`和查询位置；前端不提前显示完成 |
| 状态冲突 | `409 Conflict` | 返回当前状态、`currentStateVersion`和可用动作 |
| 无权限/授权缺失 | `403`或项目错误码 | 记录`correlationId`；不得仅靠按钮隐藏实现权限 |
| 依赖异常 | 稳定错误码 | 包含`retryable`、原因、当前状态和人工兜底提示 |
| 列表查询 | 稳定排序+cursor | 断线后按cursor补齐；补齐期间显示同步中 |
| 文件上传 | 上传会话+业务引用 | 校验大小、摘要、恶意内容和访问权限；不把大文件塞进业务JSON |

### 7.2 最小对象

| 对象 | 必须字段 |
|---|---|
| Command | `commandId, clientRequestId, vehicleId, commandKey, dispatchChannel, status, stateVersion, createdAt, operatorId, correlationId` |
| Task | `taskId, commandId, vehicleId, status, receiptStatus, assigneeId, dueAt, sourceAlertId, stateVersion` |
| OutboxMessage | `messageId, aggregateType, aggregateId, eventType, sequence, status, retryCount, nextRetryAt` |
| DirectControlAttempt | `attemptId, commandId, action, authoritySnapshotId, capabilitySnapshotId, gatewayTransportStatus, gatewayBusinessResult, verificationStatus, safetyHold` |
| FeedbackRecord | `feedbackId, taskId, version, result, submittedBy, submittedAt, evidenceRefs` |
| WorkItem | `workItemId, sourceType, sourceId, assigneeId, status, nextAction, dueAt, dueAtSource, escalatedAt` |
| AuditLog | `auditId, actorId, action, targetType, targetId, before/after摘要, result, reason, serverAt, correlationId` |

### 7.3 事件主题

`vehicle.snapshot`、`vehicle.delta`、`commands.changed`、`tasks.changed`、`alerts.upsert`、`incidents.changed`、`direct-control.changed`、`direct-verifications.changed`、`work-items.changed`、`notifications.changed`、`shift-handovers.changed`、`system-incidents.changed`、`system.health`、`config.released`。

每个事件至少包含`messageId/serverAt/sequence/schemaVersion/correlationId`。重复、乱序和迟到事件保留原始报文及丢弃原因。

## 11. 验收清单

### 11.1 P0业务验收

- [ ] 平台端普通指令在同一事务内生成唯一`commandId/taskId/outbox messageId`；数据库失败时三者同回滚。移动端同ID运行时联动属于后续外部接入验收。
- [ ] 主体单位重复、乱序、迟到和失败回调只推进一次，并保留丢弃原因。
- [ ] 普通指令五类与移动端统一字典一致，无旧同义词进入新记录。
- [ ] 任务六态与回执状态分列；列表、详情、筛选和导出均不混用。
- [ ] 任务完成且反馈成功时告警自动归档；其他结果保留责任人、下一动作和WorkItem。
- [ ] 部分/失败反馈的WorkItem具备`assigneeId/nextAction/dueAt/dueAtSource`，逾期进入升级队列。
- [ ] 事件无锚点可只上报；区域批次逐车预检，部分失败不整体回滚。
- [ ] 直控明确受理/拒绝、超时、网络异常、迟到响应、无法核实五类场景均有安全出口。
- [ ] 直控超时期间禁止冲突运动指令和重复网关调用；异人复核后移动端只出现既有状态。
- [ ] 单席和多席运行模式切换不丢在途事项，交接不改变源对象主状态。

### 11.2 平台兼容契约与工程验收

- [ ] 平台兼容API、事件、错误码、Schema、幂等和重放夹具已通过契约测试；本期不开发或修改移动端Adapter。
- [ ] 平台端重试、断线恢复、补偿和重放按业务ID与版本收敛；未来移动端重连一致性另行验收。
- [ ] 平台生产事实不依赖浏览器localStorage、Mock或静态HTML；本期不向移动端浏览器写入业务事实。
- [ ] 所有高风险操作具备对象、当前状态、影响范围、后果、依据、强认证/复核和审计。
- [ ] API使用稳定错误码、`retryable`、`correlationId`和当前版本；前端不靠中文文案分支。

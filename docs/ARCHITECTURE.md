# 基础功能架构

## 1. 架构目标

第一阶段建立可持续演进的“平台控制面”骨架：页面能导航、对象能定位、权限有守卫、状态有单一字典、接口可替换、异常有统一出口。任何 Mock 成功都不得被解释为订阅、配置、发布或车辆侧已经生效。

## 2. 目录

```text
vehicle-road-cloud-platform/
├── apps/web/                 # 平台 SPA
│   └── src/
│       ├── app/              # Provider、Router、应用入口
│       ├── core/             # 权限、导航、状态、业务数据网关
│       ├── features/         # 按 FR/业务域组织的页面和用例
│       ├── mocks/            # 可替换的演示仓储
│       └── shared/           # 无业务归属的展示组件和样式
├── packages/contracts/       # 跨页面共享的类型、状态与接口契约
├── docs/adr/                 # 架构决策记录
└── scripts/                  # 边界与质量检查
```

## 3. 模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| FR-1 服务目录与权益 | 服务、Offering、Capability、Entitlement事实 | 订阅审批、发布结果 |
| FR-2 服务订阅 | 申请、预检、审批、实例、控制意图和退出 | 配置事实、节点发布事实、车辆使用事实 |
| FR-3 参数配置 | ConfigRevision、配置校验和有效配置快照 | 订阅授权、发布执行 |
| FR-4 测试发布运行 | Qualification、Release、NodeApplication、Control Receipt | 扩大权益、伪造订阅状态 |
| FR-5 证据与运营 | RuntimeHealth、DeliveryEvidence、Incident、WorkItem | 改写上游对象事实 |
| FR-6 平台治理与接入 | Partner/租户、ApplicationClient、环境绑定、端点/凭证引用、准入与生命周期操作意图 | 替代主体角色授权、保存私钥或直接改写生产身份 |

## 4. 前端数据规则

- 服务端事实使用 TanStack Query；跨页 UI 状态不复制服务端对象。
- 页面只引用 `core/data/subscription-gateway.ts`，由该文件统一选择数据实现；`features/` 不直接引用 `mocks/`。
- 写操作必须携带 `idempotencyKey` 和 `etag`，当前骨架只定义接口，不发送生产请求。
- 页面通过 `permissionCode + scope + objectState + SoD` 计算可见和可用状态；前端守卫不替代服务端校验。
- 权限策略统一由 `core/auth/permissions.ts` 计算：先验证有效权限，再验证租户、范围、环境、对象状态、SoD、自处理限制和高风险审计原因；路由和按钮复用同一决策函数。`AuthProvider` 负责向路由、壳层和页面注入当前身份，接入 OIDC/IAM 时替换身份来源即可。
- 角色目录只描述默认授权，最终有效权限由角色权限与服务端下发的显式权限合并；任何角色变更都应通过服务端审批和审计闭环。
- 列表、详情、抽屉和深链统一携带业务 ID、Revision 和来源上下文。
- 加载、空、错误、无权限、局部失败和冲突状态由统一组件表达。

## 5. 后续接入顺序

1. 冻结项目 Profile、S1 对象链和 DevelopmentStartDecision；
2. 将 `packages/contracts` 对齐 OpenAPI/AsyncAPI 生成物；
3. 用真实 Repository 替换 `src/mocks`，保留查询键和错误模型；
4. 按 StoryId 逐项启用写操作，默认关闭未评审切片；
5. 逐项评审 FR-1～FR-6 的真实读写接口，再按证据来源接入运行回执和工单系统。

| P15 | 运营指标、门禁概览和待办入口 | Mock 汇总，不推断运行事实 |

P02、P03、P06 与 P08 的 Mock 写路径保留了幂等键、固定 Revision、reasonCode 和结果边界，目的是先验证交互及契约语义。P02 草稿、P03 提交、P06 补正动作和 P08 决定回执均存储于浏览器会话。接入真实 API 时必须由服务端再次执行权限、对象状态、职责分离、ETag、输入有效性和幂等校验。

目前左侧导航呈现完整平台模块结构；只有已接通的只读或演示切片可点击，其他功能禁用。P09/P10 中未接入的跨系统事实始终显示为未接入，不以订阅状态推断配置、发布、运行或车辆端结果。P14 只通过订阅详情进入，避免把诊断汇总误解为新的权威状态。FR-5 页面展示由回执、车端回传或监控系统提供的演示记录；具备权限的角色可提交确认、转派和恢复确认意图，回执落库但事件状态仍由监控/工单系统后续事实回传，处置完成必须回到证据链确认。

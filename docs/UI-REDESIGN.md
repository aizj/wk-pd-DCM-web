# 运营后台视觉与信息层级调整（2026-09-16）

## 参考原则

- [Ant Design 布局规范](https://ant.design/docs/spec/layout-cn/)：以固定导航和可伸缩内容区组织中后台，使用一致的间距与栅格。
- [Ant Design 页面布局范式](https://2x.ant.design/docs/spec/layout-cn)：列表优先呈现决策所需信息，次要事实递进到详情。
- [Arco Design Pro](https://pro.arco.design/) 与 [TDesign Starter](https://tdesign.tencent.com/starter)：保持导航、筛选、表格、详情和状态反馈的一致性。仅借鉴通用结构，不复制界面。

## 本轮落地

1. 全局改为浅色导航、白色顶栏和低对比背景；去除深色渐变、大阴影与重复边框。
2. “订阅实例”由卡片套表格改为一张分组表格：列表显示订阅、实例、版本、生命周期、开通条件和外部事实；完整编号及更多事实进入详情。
3. 演示提示压缩为单行说明，未接入状态保持未知，不伪装为成功或健康。
4. 窄屏改为抽屉导航和实例卡片；详情状态按实例分项展示，不再依赖横向滚动表格。
5. “我的工作台”以最近申请、待处理事项、办理进度为主信息架构，突出可执行下一步，避免堆叠泛化驾驶舱图表。
6. “申请管理”采用申请概览、流程提示、紧凑申请表格和移动端卡片，明确区分申请状态、准入检查与服务开通状态。
7. 配置管理与联合测试沿用同一套列表、状态筛选、信息抽屉和移动端卡片，保持从审批到交付的操作连续性。
8. 服务发布沿用同一套发布计划列表和节点进度表达，明确区分发布执行结果与车辆端实际交付证据。
9. 服务目录与权益页采用“可申请能力”和“企业授权边界”分层展示，避免把平台服务能力误当成企业已获授权；服务详情匹配当前租户有效权益，只有匹配有效权益时才开放申请入口并传递服务上下文。
10. 运行与交付证据采用“接收—展示—交互”纵向证据链，事件页采用“类别—严重度—状态—责任人”结构；未知、失败和已恢复保持明确区分。
11. 运行诊断从订阅详情进入，以原子实例为最小判断单元，将配置、测试、发布、证据和事件并列呈现，避免把订阅级状态误当作车辆端结果。
12. 版本比较使用“基准版本 → 目标版本”的双选择器和字段级差异表，明确影响程度及是否需要重新测试，不把版本号变化简化为已生效。
13. 变更与续期采用“变更意图—影响评估—重新审批—重新交付”的四段路径，仅在影响评估可执行时提交待审批申请。
14. 控制与退出采用“动作—范围—门禁—退出证据”结构，高风险动作提交待核验计划，不直接切换状态，必须明确服务端鉴权、职责分离和回执要求。
15. 访问控制改为“总览—角色管理—角色权限配置—主体授权—权限目录—审计查询”的独立页面结构；总览只提供账号态势、权限边界和模块分流，不承载管理表单。角色权限配置展示角色模板与功能权限矩阵，支持按模块、风险和关键字筛选并对当前筛选结果批量启用/移除，写权限受 `GOVERNANCE.ROLE.CONFIGURE` 控制；主体授权明确区分用户、服务账号和组织，并支持按主体类型、角色、环境和状态筛选，展示有效期与待审批状态；权限目录标识角色继承与显式授权来源。
16. 租户/合作方准入从主体角色授权中独立出来，入口为 `/fr1/partners`。页面分为“合作方与租户”和“应用与环境”两个工作区，分别管理 PartnerSummary、ApplicationClient、环境范围、端点/凭证引用、配额及申请记录；`FR6.PARTNER.READ/REQUEST/MANAGE` 控制查看、申请和管理动作，申请只生成待审核回执，不直接创建生产身份。
17. 端点和凭证治理使用独立入口 `/fr1/endpoints`，按端点粒度展示脱敏地址、网络区、认证方式、凭证签发方/有效期、端点状态和信任判断；详情查询接入网关回传的 DNS/网络、TLS、证书链、应用身份、Scope、协议握手六项核验记录，逐项显示状态、时间、来源、traceId 和补救建议；连接测试、轮换和吊销必须绑定端点与环境并统一生成受审计操作回执，不在浏览器保存私钥或 Token。
18. 访问复核从主体授权实例中独立出来，入口为 `/governance/access-reviews`。页面按用户/服务账号/组织、租户、角色、环境、资源、动作、数据分类、状态和有效期筛选复核对象；保留、收窄、撤销只提交待审批结论，并阻断被复核主体自审。
16. 对接状态按系统、数据域、环境、状态、Owner、下一步表达；系统接入状态与业务服务成功、车辆端展示事实保持分离。
17. 审批队列先表达“我的待办—状态—风险—时限—下一步”，再进入单条审批详情；队列定位与审批决定保持分离。审批决定还需服务端复核当前处理人匹配和禁止申请人自审。
18. 配置详情按“版本基线—参数分组—当前值—状态—来源/校验”表达；参数变更申请按“目标配置—变更类型—原因—重测门禁—审批回执”表达，不绕过审批生成新Revision。
19. 联合测试详情按“输入门禁—测试项—结果—证据等级—阻断原因”表达；通过进入门禁的任务可提交“启动联合测试”意图并查看排队回执，测试任务状态不能替代单项结果，测试通过也不能替代发布和车辆证据。
20. 发布详情按“版本—进入门禁—变更窗口—节点回执—回退计划”表达；满足测试门禁的计划可提交“启动发布”意图并查看排队回执，部分节点完成不能被展示为整体发布成功。
21. 运行证据详情按“证据链状态—阶段事件—来源—关联号—未知原因”表达；事件详情按“根因—影响—SLA—时间线—恢复证据”表达。具备 `FR5.INCIDENT.UPDATE` 的角色可提交确认、转派、恢复确认意图并查看回执，处置完成不等于车辆证据恢复。
22. 变更与续期按“目标变更—权益/版本影响—重新交付门禁—待审批回执”表达；只有影响评估可执行时开放提交，不把预览当作已变更。
23. 控制与退出按“动作—原子实例范围—控制门禁—退出清单—待核验回执”表达；控制计划不直接切换状态，终止动作必须保留退出证据要求。
24. 补正任务按“问题要求—材料引用—独立复核—重新检查”表达；补正动作只提交材料引用和处理意图，不直接关闭任务或改写准入结果。

## 验证范围

- 已在当前窄预览窗口检查列表、搜索、重置、导航抽屉及实例详情。
- 已通过 `npm run check`（边界检查、类型检查、测试和构建）。
- 配置管理已提供配置版本详情和配置变更/回退申请演示切片；申请仅生成沙箱待审批回执，尚未接入真实参数保存、配置校验、发布、运行和车端事实。
- 运行与交付证据、事件与工单已提供演示切片；事件处置支持确认、转派、恢复确认三类带幂等键的操作回执，但尚未接入真实车端日志、监控告警和工单状态回写接口。
- 访问控制已拆为独立路由：`/governance/permissions`（总览）、`/governance/roles`（角色管理）、`/governance/role-permissions`（角色权限配置）、`/governance/authorizations`（主体授权）、`/governance/permission-catalog`（权限目录）。具备配置权限的账号可编辑沙箱权限草稿并提交配置申请，在申请记录中查询本会话回执；申请仅生成待审批回执，不直接改变有效权限；尚未接入真实身份中心、角色配置审批发布和服务端策略服务。
- 授权变更申请历史和动态申请草稿均在数据网关层按目标租户与当前工作环境过滤；切换工作身份后不会继续读取旧租户或旧环境的对象记录。新增授权会校验重复授权，调整/撤销会校验目标授权实例确实存在。生产实现需由服务端/IAM执行同等隔离，前端过滤仅用于提升操作反馈。
- 租户与接入查询、详情和申请也在数据网关层按当前租户与当前环境过滤；ApplicationClient 与合作方准入申请共用幂等键和服务端权限门禁，冻结/恢复/退出、连接测试、凭证轮换/吊销只提交受审计的操作意图，生产实现需由 IAM、统一网关、证书中心/KMS 和审计中心提供真实事实。
- 联合测试已提供通过门禁后的启动意图和排队回执演示；排队不代表测试结果已通过，尚未接入真实测试调度、结果回传和发布服务。
- 服务发布已提供联合测试门禁后的启动意图和排队回执演示；排队不代表节点已完成或车辆端已生效，尚未接入真实发布调度和节点回执。
- 服务目录详情已增加当前租户权益匹配和申请上下文传递；无有效权益时不开放申请入口，申请向导仍需重新执行准入校验。
- 申请向导已支持从服务/权益上下文创建演示环境草稿，校验有效期、接入方式、车型能力和Coverage后进入P03；固定示例仍为只读，草稿回执仅保存在当前会话。
- 变更与续期已提供影响评估、门禁和待审批申请回执；申请不直接修改订阅或生成新Revision，尚未接入真实变更审批与版本服务。
- 控制与退出已提供原子实例范围、状态门禁、退出清单和待核验控制计划回执；计划不直接切换状态，尚未接入真实控制执行、职责分离和退出证据回写。
- 补正任务已提供材料引用、重新检查意图和幂等回执；不直接上传文件、关闭任务或改写检查结论，尚未接入真实材料存储、独立复核和检查服务。
